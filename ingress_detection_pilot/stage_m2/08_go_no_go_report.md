# 08 Go / No-Go及Q1–Q7

**NO-GO：当前不进入跨Chunk上下文一致性检测算法设计。**完成M2后停止，未授权/未执行M3、新算法实现或训练。

本阶段为人工构造小样本机制探索；40基础源、80良性/攻击变体，每个条件共享这些源。不是自然业务分布、不是正式论文测试或算法收益证明。

**Q1：切分是否造成FP/FN？** 本面板中，A完整→B跨块新增良性FP 13条、新增恶意FN 17条；同时纠正FP 0条、FN 0条。存在分类变化时也不能将全部变化单独归因语义丢失，因为官方载体分配不同。固定全文Shadow提供组合边界影响的独立核对。

**Q2：更可能的原因？** 完整核心已经FP 19/40、FN 0/40，属于F5候选。官方边界与Shadow/等长恢复的交集见三角核对；F1语义、F2布局、F3局部内容/位置可共存。F4按非核心独占阈值单列，不把它与检测器误判混同。

**Q3：最强可重复证据？** 边界/局部输入表示敏感性H2的干预证据最直接：固定512长度和核心局部位置、仅替换CLS时13条良性判定翻转，攻击判定不变；但这是非标准反事实，不能直接宣布官方CLS布局是唯一原因。另一个强重复现象是F5：完整语义下19/20个Hard-Benign被误报，不是分块才产生。相同ID的全局位置160次重复完全不变。单纯语义丢失H1的独立贡献尚未分清，严格官方/Shadow/等长恢复交集仅2源且同一攻击族。

**Q4：恢复能否无明显攻击损失地纠错？** 恢复不是预设成功。native两类的纠错/新错为benign 21/0、attack 0/0；等长512为benign 0/7、attack 27/0。即使没有明显新FN，40个固定模板攻击也不能证明非劣或普遍安全。

**Q5：值得进入算法设计吗？** NO-GO：当前不进入跨Chunk上下文一致性检测算法设计。预定数值筛查=True；等长恢复的三角交集=2。数值门只作筛查，必须连同共同作者、共享payload/引用框架、官方载体变动、Shadow残余混杂和小样本限制判断，不能把通过工程或统计门称为方法有效。

go_no_go.json保留的是预声明数值筛查及“待机制审查”的中间建议，**最终决策以decision_review.json和本报告为准**。本轮数值筛查通过，但13个良性native恢复交集没有获得等长恢复纠错支持；严格交集只有2个同一攻击族源，未达到3源/至少2语义族的可重复机制要求。当前不开发算法。这个追加归因复核不改变输入、分数、阈值或原预声明结果。

**Q6：若值得，最小模块/强Baseline/风险？** 若进入方案设计，最小候选仅应针对已证实的边界错误决定何时查看相邻上下文，不先堆叠多尺度/长度校准。强Baseline须包含固定512非重叠Max、独立校准充分调阈值的Global/Domain Max、普通固定重叠窗口及每块特殊token规范化消融、可容纳完整核心的诊断oracle。未来统一新源分组/误报预算、同时比较TPR与实际FPR；本轮未实现这些方法。主要风险为共享模板/构造填充、引用语义标签争议、上下文稀释恶意指令、新FN、Max背景放大、开销增加和从探索集调参。

**Q7：若不值得，停止什么、转向什么？** 若No-Go，停止把一般长文档错误默认解释为语义上下文丢失，暂停LCMD和跨Chunk一致性模块。下一优先问题是检测器对“引用的恶意措辞”与“正在对Agent发出的恶意要求”的意图区分：用新的短、完整、不同引用/主动指令模板，检验F5，而非先增加分块复杂度。若本轮尚有局部边界信号，也只保留为待独立验证的具体案例。
